Open Geotechniek Studio

From BRO cone test to site drawing and report, in one free app

Open a GEF or BRO file, or find every cone test around your site on the map. View qc, fs and Rf with an indicative soil layering, place the points on a site drawing and turn it into a report.

Features

Everything for cone tests and boreholes, in one app

Start with the highlights, or pick a topic.

01 Cone tests

Read a cone test at a glance

Cone resistance, sleeve friction and friction ratio side by side on one depth axis in NAP. The app divides the test into indicative layers; you adjust the layer boundaries yourself and see a normalized Qt/Fr/Bq/Ic analysis per point.

Learn more

02 Map and BRO

All BRO data around your site

Search by address or RD coordinate and load the cone tests, boreholes and groundwater wells from the Dutch subsurface register (BRO) in the visible area. Add aerial photos from 2016 onward, the AHN elevation map, cadastral boundaries or BAG buildings underneath.

Learn more

03 Site drawing

A site drawing without a CAD program

Place cone tests, boreholes or a whole grid of tests on the map, with dimension lines, RD coordinates and notes. Put a PDF or image underneath and export to PDF on A2 or A3, with a completed title block.

Learn more

04 Report

A report for the project file

Choose what goes in: cover, coordinate table, overview map, a page per cone test, the legend and the metadata. Set the chart scale, for example 1:50 across several sheets.

Learn more

  • Open GEF and BRO-xml

    Cone tests in GEF or BRO-xml, boreholes (BHR-GT, GEF-BORE) and groundwater wells (GMW). Several tests in one file too.

  • qc, fs and Rf by depth

    Charts on one depth axis in NAP, with values under the mouse and pore pressure (u2) where measured.

  • Indicative soil layering

    Automatic layering on qc and Rf, with minimum thickness and hysteresis. Adjust boundaries yourself and export the layers as JSON with provenance.

  • Normalized analysis

    Qt, Fr, Bq and Ic per measuring point, with the stresses you enter yourself.

  • Boreholes and groundwater

    Borehole logs with layers, colour and admixtures, and groundwater wells with their time series.

  • Data checks

    Messages about columns, units, voids and depth, with the line in the source file. Export the check as JSON or CSV.

  • Several cone tests side by side

    Each file in its own tab, or a project with several tests on one depth axis.

  • Search by address

    Through the PDOK Locatieserver by address, place or RD coordinate.

  • Load BRO data

    Cone tests, boreholes and groundwater wells in the visible area, also in large areas above the 2,000-object limit.

  • PDOK map layers

    Topography, aerial photos of today and of 2016 to 2025, AHN, cadastre, BAG, BGT, zoning plans and historical maps.

  • Measure and export

    Measure distances on the map and save the map as an image.

  • Grid of cone tests

    Lay out a whole grid of cone tests on the drawing in one go.

  • Drawing tools

    Lines, areas, dimension lines and RD coordinates, with move, copy, rotate, trim, extend, mirror and offset.

  • PDF or image underneath

    A PDF page, photo or SVG frame as background, cropped and to scale.

  • PDF on A2 or A3

    With title block, scale bar and north arrow. The desktop app also exports to DWG.

  • PDF report

    Cover, coordinate table, overview map, a page per cone test, legend and metadata, each on or off.

  • Source-faithful GEF export

    Writes back the original columns, voids and RD/NAP codes, and stops on doubtful source data.

  • Own project file

    Keep cone tests, layers and drawing together in an .ifcgeo file. The desktop app also exports CSV and GeoJSON.

  • Settlement of one layer

    Concept worksheet in the desktop app, with units and intermediate steps visible.

  • Pad foundation (EC7)

    Concept worksheet for a centrally loaded rectangular pad following EC7 Annex D, in the desktop app.

  • MCP and HTTP API

    An AI assistant or your own script reads cone tests, divides layers and calculates through MCP or a local HTTP API.

  • Node library and SDK

    The same GEF reader, checks and calculations as a separate Node library, plus a native SDK for your own software.

  • Five themes

    Light, dark, Blueprint and two high-contrast themes, in the style of all OpenAEC apps.

Frequently asked questions

Which files can I open?

Cone tests in GEF and BRO-xml, boreholes as BHR-GT or GEF-BORE, groundwater wells (GMW) and your own projects in .ifcgeo. You can also open BRO files straight from the map.

Do I need to install anything?

No. The web version works straight in the browser. For the calculations, DWG export and CSV or GeoJSON there is the desktop app for Windows, macOS and Linux.

What does Open Geotechniek Studio cost?

Nothing. The app is free and open source under the MIT licence, with no account or subscription.

In which format is my work saved?

In an .ifcgeo file, an open JSON format with IFCX content. You can also export a cone test back to GEF.

Which systems does it run on?

Windows, macOS (Intel and Apple Silicon) and Linux (.deb and AppImage), and any modern browser. The installers are signed.

Does it fit Dutch practice?

Yes. It reads GEF and the BRO formats with their quality regimes, describes boreholes following NEN 5104 and works in RD coordinates and NAP. The layering is indicative and does not replace an assessment by a geotechnical engineer.

What can an AI assistant do with it?

The desktop app and the Node library have an MCP server (Model Context Protocol). With it, an assistant such as Claude can read cone tests, fetch BRO data, divide layers, calculate and create a report. There is also a local HTTP API for your own scripts.

Do I need an internet connection?

Only for the map and the BRO. Your own files are processed on your computer and not uploaded anywhere.

Can I export to IFC?

Not yet. An IFC4x3 export is switched off until it meets the schema. The app does already build an experimental IFCX view of your data.

Technology

For those who want to know how it is built.

Tauri 2

A thin native shell in Rust for Windows, macOS and Linux, with small, signed installers.

React en TypeScript

The same interface in the browser and on the desktop, with charts drawn on canvas.

Shared core

One GEF reader, check and export for browser, desktop and Node, tested against Bedrock and pygef.

Leaflet en PDOK

Maps in RD and WGS84 with the open map services of the Dutch Kadaster and PDOK.

BRO REST API

Cone tests, boreholes and groundwater wells straight from the public Dutch subsurface register.

MCP, HTTP and SDK

An MCP server, a local HTTP API, a Node library and a native DLL/.so for integrations.
